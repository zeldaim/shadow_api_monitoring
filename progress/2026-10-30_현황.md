# ELK 구축 현황 (2026-10-30 갱신)

> `HANDOFF_진행상황.md`(10/29 오전 기준) 이후 바뀐 내용. 두 파일이 다르면 이 파일이 최신이다.

## 바뀐 점

- ELK VM 위치: 노트북이 아니라 **같은 대역 로컬 PC의 VMware** (NAT, `192.168.100.137`, DHCP라 바뀔 수 있음)
- 터널 대상: Wazuh 서버가 아니라 **WEB 서버**(FortiGate `192.168.0.141:2222` → `192.168.20.10:22`)로 역방향 터널
  ```bash
  ssh -p 2222 -N -o ServerAliveInterval=30 \
    -R 19200:localhost:9200 -R 15601:localhost:5601 \
    ubuntu@192.168.0.141
  ```
- WEB 서버의 Filebeat는 `localhost:19200`을 보므로 ELK VM IP가 바뀌어도 수집에는 영향 없음
  - IP가 바뀌면 `kibana.yml`의 `server.publicBaseUrl`만 고치면 됨

## 상태

| 항목 | 상태 |
|---|---|
| Elasticsearch · Kibana 설치 | ✅ 완료 |
| SSH 역방향 터널 | ⚠️ 인프라 VM이 꺼져서 끊김 (기술 문제 아님) |
| Filebeat | ✅ 설치, 설정 전 |
| Metricbeat setup | ⛔ `context deadline exceeded` (터널이 끊겨서) |
| Kibana 대시보드 | ⬜ 미시작 |

## 다음 단계

1. 인프라 VM 재기동 → 터널 재연결
2. WEB에서 터널 확인: `curl -sk https://localhost:19200 -o /dev/null -w '%{http_code}\n'` → `401`이면 정상
3. 터널 상시화: ELK VM에 `autossh` + systemd 서비스 (끊겨도 자동 재연결)
   ```ini
   # /etc/systemd/system/elk-tunnel.service
   [Unit]
   Description=Reverse SSH tunnel to WEB server
   After=network-online.target

   [Service]
   ExecStart=/usr/bin/autossh -M 0 -p 2222 -N \
     -o ServerAliveInterval=30 -o ExitOnForwardFailure=yes \
     -R 19200:localhost:9200 -R 15601:localhost:5601 \
     ubuntu@192.168.0.141
   Restart=always

   [Install]
   WantedBy=multi-user.target
   ```
   SSH 키 교환이 먼저 필요하다 (`ssh-keygen -t ed25519` → `ssh-copy-id -p 2222 ubuntu@192.168.0.141`).
4. Metricbeat setup 재시도, Filebeat 설정·기동
5. Kibana Data View `filebeat-*` + Shadow API 대시보드 (가이드 7장)

## 미확인

- Apache 로그의 클라이언트 IP가 실제 IP인지 Docker 브리지 IP(`172.x`)인지
- 쇼핑몰 API 명세: 팀 레포 `web/src/public/docs/openapi.yaml`에 `/api/v2/*`만 있음 → 이걸로 `api-inventory` 작성 가능, v1은 명세에 없으므로 Shadow로 분류됨
